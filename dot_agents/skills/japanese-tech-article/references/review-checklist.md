# 公開前レビューと改稿チェック

**重大度順に**指摘する。点数やチェック率ではなく、読者に影響する具体的な問題を根拠とともに示す。

## Critical: 公開を妨げる問題

- 実在しない仕様・API・参照元・測定結果・引用を、事実として書いている。
- 実行していないコードやコマンドを「動作確認済み」と誤記している。
- 手順の省略や誤りにより、重大なデータ喪失・漏えい・セキュリティ問題が発生しうる。
- 記事の主要結論が根拠と矛盾する。
- 投稿先の公開設定が意図せず公開状態になっている。

## Major: 記事の価値を大きく下げる問題

- 読者の問いと構成・結論が噛み合わない。
- **文法的には正しいのに記事として不自然**：読み手のいないREADME要約、抽象的な案内の連発、同じ段落構造・文末の反復、根拠を羅列するだけで語りの軸がない。
- 重要な情報を取捨選択できず、動向紹介・比較・手順が混在して読者の判断につながらない。
- バージョン、前提条件、比較条件、検証状態が不明。
- 説明に必要な因果関係や概念の区別が欠けている。
- 原稿の独自の試行・失敗・判断・制約が推敲で失われた。
- コード、コマンド、設定に齟齬があり再現が難しい。
- リンク切れや出典の欠落が中心的な主張に影響する。
- 投稿先のFront Matterや独自記法が不正。

## Minor: 局所的な改善

- 主述のねじれ、曖昧な指示語、読点や段落の読みづらさ。
- 局所的な冗長な言い回し、不必要な定型句、無意味な装飾（**記事全体にわたる単調さはMajor**）。
- 表・箇条書き・見出しの使い過ぎ、説明の重複。
- 表記揺れ、言語指定なしのコードフェンス、代替テキスト不足。

## レビュー結果フォーマット

1. **結論**: 公開可否の判断、レビュー対象と検証範囲。
2. **指摘**: 重要度 / 場所 / 内容 / 根拠 / 改善案。
3. **未確認事項**: 取得できないソース、未実行テスト、著者に確認が必要な判断。
4. **良好な点**: 記事固有の価値を壊さないための短い確認（必要な場合のみ）。

改稿では、各指摘に対して **keep / change** の判断をし、十分良い箇所は変更しない。リライトの規模が大きいほど、元の主張・重要度・検証状態を変更後と照合する。
