# 回帰テスト計画

目的: v0.2のNeovim記事を入力とし、同じプロンプトでv0.3と比較する。現在の成果物は**Skillの設計**であり、モデル上でv0.3を実行したA/B比較ではない。

## 再現条件

- 同じモデル、同じthinking設定、同じ時点の検索可能性、同じ入力プロンプトを用いる。
- upstreamの読み込み状況とスクリプトのバージョンを記録する。
- 「2024年からワープして来たNeovimユーザー向けに2026年現在のNeovimの状況を教えるQiita記事」を生成する。
- v0.2記事の全文とv0.3出力をブラインドで比較する。最低でも、書き手とは別の評価者に日本語の自然さを見てもらう。

## 自動・半自動の観測

- natural-japaneseのlint（tech）: finding分類と各件への対応・保留理由。
- natural-japanese outline: 見出しと段落頭の繰り返し、無関係な予告。
- yomiyasu run/verify: 意味のズレ候補、最終稿の一致。
- japanese-tech-writingチェックリスト: 6軸項目（点数が必要な場合は上流基準の採点）。
- 当Skillのplatform lint: 投稿形式のみ。

## 人間の判定

初見で「日本語が自然か」（1〜5段階）に加え、読者が理解できるか・原稿の筆者にない体験談がないか・変更の重要度が伝わるかを個別に評価する。元記事の日本語が1〜2というユーザーフィードバックを基準として記録し、改善したと**推測して**合格にしない。

## 失敗条件

- 形式チェックだけで「日本語のlint済み」と主張する。
- 指摘を機械的に消し、技術的に必要な否定・留保まで削る。
- 文末を散らしただけで段落・文章構造を変えていない。
- 読者にない経験や、筆者の試行・主観を勝手に加える。
- 以前と同様に全部の節がほぼ同じ構成の連続となる。
